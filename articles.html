How to Structure a Semantic HTML Page

By Al Aqsa Reto Wijaya · January 12, 2026 · 5 min read

Most people start a page with a div and keep going. It works, but it throws away the information the browser and assistive technology could have used for free.

The skeleton

Every page needs the same bones:

  • header at the top, holding the logo and navigation.
  • nav for the set of links that move you between pages.
  • main wrapping the content unique to this page. One per document.
  • footer for copyright, secondary links and contact details.

Section versus article

This is the pair people get wrong. Use section for a thematic chunk of a page — a group of projects, a block of reviews. Use article for something that would still make sense syndicated on its own: a blog post, a product card, a comment.

A rough test: if you pulled it out and put it in an RSS feed, would it stand alone? That is an article.

Labelling sections

Give every section an accessible name with aria-labelledby pointing at its heading. Screen reader users can then jump between regions instead of listening to the whole page. 

<section aria-labelledby="projects-heading">
    <h2 id="projects-heading">Projects</h2>
</section>

Headings in order

One h1 per page, then h2 for major sections, h3 inside those. Do not skip levels to get a smaller font size — that is what CSS is for.

Why this pays off later

When the stylesheet arrives, it can target real landmarks instead of guessing at class names. You end up writing less CSS, and the markup survives a redesign.

SEO Meta Tags That Actually Matter

By Al Aqsa Reto Wijaya · February 3, 2026 · 4 min read

You can put a hundred tags in a head. Five of them do almost all the work.

1. Title

The single strongest on-page signal. Keep it under about 60 characters, put the distinguishing word first, and make it unique per page.

<title>Projects | Aqsa | Frontend Developer</title>

2. Description

Not a ranking factor, but it is the snippet people read. Around 150–160 characters, written as a sentence, not a keyword list.

3. Canonical

Tells search engines which URL is the real one when the same content is reachable several ways.

<link rel="canonical" href="https://example.com/projects.html">

4. Open Graph

Controls the preview when someone pastes your link into a chat app. At minimum: og:type, og:title, og:description, og:url and og:image.

5. Twitter card

Same idea for X. summary or summary_large_image, plus title and description. If Open Graph is present, Twitter falls back to it, so this is mostly belt and braces.

What to skip

keywords has been ignored by major engines for years. revisit-after and rating are noise. Add keywords anyway if you like — it costs nothing and some smaller crawlers still read it.

Per page, not per site

The most common mistake is one shared head with a single title and description. Every page needs its own, or every page competes for the same query.

Building Forms That Are Easy to Style Later

By Al Aqsa Reto Wijaya · March 18, 2026 · 5 min read

Forms are where structure work pays off fastest. Get the markup right and styling is mostly a matter of selecting the elements that are already there.

Always pair label with input

The for attribute on the label must match the id of the input. This is not optional — without it, screen readers announce a bare text box with no name.

<label for="email">Email</label>
<input type="email" id="email" name="email" required>

Wrapping the input inside the label also works, but the explicit pairing is easier to read.

Group related fields

fieldset draws a box around a group; legend names it. A contact form naturally splits into "your details" and "your message".

Let the browser validate

These attributes do the job of a lot of JavaScript:

  • required — the field must be filled.
  • type="email", type="tel", type="url" — format checks and the right mobile keyboard.
  • minlength, maxlength, pattern — length and format rules.
  • autocomplete — lets password managers and browsers fill the form correctly.

Use the right control

select for a short fixed list, textarea for multi-line text, input type="checkbox" for independent toggles, radio buttons when exactly one option must be chosen. Do not build a dropdown out of divs.

Name attributes matter

Whatever server or handler receives the form reads the name attribute, not the id. Every control that should be submitted needs one.

Buttons, not divs

<button type="submit"> is focusable, keyboard-operable and announced correctly. A styled div with a click handler is none of those things.

Why You Should Not Style During the Structure Phase

By Al Aqsa Reto Wijaya · April 9, 2026 · 4 min read

The roadmap.sh basic HTML project says it outright: do not style the website, only focus on the structure. That instruction is doing more work than it looks like.

What goes wrong when you mix them

You pick an h3 because it renders at the size you wanted. You add a wrapper div because you need a flex container. Six weeks later the markup describes your old design instead of your content, and the stylesheet is full of selectors that exist only to undo other selectors.

Structure is a decision about meaning

Is this a list of projects or a list of articles? Is that a standalone post or part of a longer page? Those questions have right answers that do not change when the design does. Answering them first means the document stays correct.

Styling is a decision about presentation

Those answers change constantly. Keeping them in a separate file means a redesign touches one file, not eight.

The practical sequence

  1. Write the content as plain text, in order.
  2. Wrap it in semantic elements: header, nav, main, section, article, footer.
  3. Add headings in a single hierarchy, one h1 per page.
  4. Add the head metadata: title, description, canonical, Open Graph.
  5. Only now open a stylesheet.

How to tell you are done

Turn off CSS in the browser. If the page still reads as a sensible document — title at the top, sections in order, links that make sense — the structure is right. If it collapses into an undifferentiated wall of text, the markup was carrying the design and the design was carrying the markup.

One more thing

This is also the cheapest accessibility win available. Screen readers, reader modes and text extraction tools all read the document, not the stylesheet. A well-structured page degrades gracefully everywhere for free.
